# Fixed UTC offset instead of a DST-observing timezone

A Building's Interval Readings are stored with naive local timestamps, which also serve as the upsert identity used to correct or re-upload data. A DST-observing IANA timezone repeats one wall-clock hour every fall-back, so two distinct real-world readings can collide on the same naive timestamp and silently overwrite one another. We decided a Building's local time is a single fixed UTC offset for v1, not an IANA zone, so no wall-clock hour is ever repeated and every timestamp stays a stable, unambiguous upsert key. We considered keeping IANA timezones and resolving the fall-back collision with a heuristic, or requiring uploads to carry explicit UTC offsets per row, but both add complexity disproportionate to v1's needs. Trade-off: displayed daily/monthly boundaries will drift by up to an hour from true local wall-clock time for part of the year in DST-observing regions.
